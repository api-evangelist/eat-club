# EAT Club

> EAT Club is a corporate meal-delivery platform founded in 2010 in Redwood City, California
> and acquired by Compass Group USA in October 2020, where its ordering, production and
> delivery technology now sits inside Compass Digital Labs. It runs a "virtual cafeteria"
> for offices without on-site dining: each employee picks an individually packaged meal from
> a rotating daily menu, and every order for a building arrives in one synchronized delivery.
> EAT Club publishes no developer program — no API reference, no machine-readable
> specification, no SDK, no webhooks catalog and no `/.well-known/` documents. This file is
> generated by API Evangelist from public sources; it is not published by EAT Club.

## API surface

- **None published.** As of 2026-08-12 there is no EAT Club developer portal, API reference,
  OpenAPI/Swagger document, GraphQL endpoint, AsyncAPI, MCP server or A2A agent card at any
  EAT Club host. `api.eatclub.com`, `developer.eatclub.com`, `developers.eatclub.com`,
  `docs.eatclub.com`, `app.eatclub.com`, `portal.eatclub.com` and `admin.eatclub.com` all
  return NXDOMAIN.
- The ordering application at `https://www.eatclub.com/menu/1` is a first-party React SPA
  ("aphrodite" bundle) that talks to an **undocumented, session-authenticated** JSON backend
  under `https://www.eatclub.com/api/v3/`. It is internal plumbing for the app, not an
  offered API: there is no reference, no key issuance, no terms covering programmatic access,
  and unauthenticated calls are rejected (`/api/v3/menu-dates/` returns HTTP 400
  `"Unauthenticated user with no location in session"`). Do not treat it as a public contract.
- Identity federation is the one supported machine integration: EAT Club is listed in the
  Okta Integration Network with SAML SSO and SCIM provisioning, configured through Okta
  rather than through an EAT Club developer surface.
